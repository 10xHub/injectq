# injectq 0.6.0 — rewrite plan

Status: proposal, not started. Target: one release, **0.6.0** (no 0.5.x patch).
Date: 2026-11-23. Baseline: 0.5.0 (`main` @ aba47e7).

Goals, in priority order:

1. **Correct** — no container or scope leaks between tasks, threads or requests; sync and async give the same answers.
2. **Fastest pure-Python DI library** on per-call cost, while keeping injectq's cheap startup and live rebinding/overrides.
3. **One implementation of each thing** — no sync/async forks, no second resolver, no parallel scope managers.
4. **Smaller public surface that does what the docs say.**

Evidence for everything below was produced by running code against 0.5.0. Scripts and raw numbers:
`/tmp/claude-1000/-home-shudiptot-projects-injectq/81944544-b9a5-40b8-aa14-8a5bca70abae/scratchpad/` (`repro.py`, `repro_fastapi.py`, `verify*.py`, `bench/`). That folder is temporary — the benchmark suite should be moved into the repo (see §7).

The prototype is a scratch engine (`bench/scripts/proto.py`, its tests pass) that implements the design in §3.
It beats every library measured on S2–S7 and is within ~15 ns of the Cython library on S1.
Profile of 0.5.0 S2: ~80 % of the time is `inspect.signature` + `get_type_hints`, re-run for every class on every resolve
(`utils/helpers.py:get_function_dependencies`, `core/resolver.py:_instantiate_class`, `decorators/_inject.py:141`).

Other measured costs:

- `import injectq.integrations.fastapi` takes **1.5 s** when fastmcp is installed (`integrations/__init__.py` imports all three integrations; `fastmcp.py` imports fastmcp at module load). 39 ms without.
- `import injectq` 49 ms, ~33 ms of it is the eager `injectq.testing` import pulling in asyncio.
- FastAPI request with 3 `InjectFastAPI` deps: 416 µs vs 200 µs if the dependency were `async def` (sync deps go through the threadpool).
- `thread_safe=True` serialises threads: the container lock is held while user factories run (4 threads × 10 ms factory: 0.41 s vs 0.10 s), and a factory that resolves from another thread deadlocks.

## 2. What other libraries do (and what we copy)

Source read: wireup 2.13.1, dishka 1.10.1, that-depends 4.3.0, dependency-injector 4.49.1 (sdists).

| Technique | Who | Gain in our prototype | Adopt? |
|---|---|---|---|
| Per-key plan computed once (signature + hints cached) | all fast libs | S2 25 → 0.79 µs (30×) | **yes — the main win** |
| Link resolvers at compile time (deps call each other's resolver directly, not `get()`) | wireup, dishka | S2 0.79 → 0.30 | **yes** |
| Generate a Python function per key with `exec`, transient subtree inlined | wireup, dishka, Injex | S2 0.30 → 0.24, S3 1.06 → 0.56 | **yes**, closure fallback for `debug=True` |
| Register generated source in `linecache` | dishka | tracebacks show generated code | **yes** |
| Generated `@inject` wrapper, only missing kwargs filled, no `bind_partial` | wireup (that-depends' `bind_partial` per call is why it's slow) | S5 17 → 0.22 | **yes** |
| Singletons baked as constants once created / factory self-replacement | wireup | S5 0.22 → 0.09, S3 0.57 → 0.42 | **yes**, tied to invalidation |
| Request scope = dict stored in a ContextVar, token set/reset | wireup, that-depends | S4 4.3 → 0.6 (beats wireup 1.06) | **yes** |
| Async short-circuit: subtree with no async factory resolves synchronously | wireup (`is_async` flag) | S6 25 → 0.34 | **yes** |
| Locks only around singleton creation, double-checked; no lock on reads | wireup | removes thread serialisation and deadlock | **yes** |
| Overrides swap an entry in the factories dict, restore stack | wireup | no recompile | **yes**, plus version bump |
| Pure ASGI middleware (not `BaseHTTPMiddleware`, which blocks ContextVar propagation) | wireup, that-depends, svcs | — | **yes** (already pure ASGI) |
| Eager whole-graph compile at container creation | wireup (8.4 ms), dishka (4 ms) | — | **no** — keep lazy compile (S7 19 µs) |
| Immutable container, rebuild for tests | dishka | — | **no** — keep live rebinding |
| Cython | dependency-injector | slower than generated pure Python in every per-call scenario except S1 | **no** |

Pitfalls others documented that the design must handle:
- `ContextVar.reset(token)` raises `ValueError` from another context (async generator closed from another task, GC finalisation; CPython #118944, #93740). Catch it and let the value lapse with that context.
- Changes made inside `to_thread` / anyio worker threads don't flow back to the caller (fine for us — we only read there).
- `loop.run_in_executor` does **not** copy context (Taskiq runs sync tasks this way) — keep an explicit fallback there.
- Overrides don't affect objects already holding an old singleton (wireup documents this) — document the same.

## 3. Target design

### 3.1 Engine

```
Registry  (mutable; bind/override/clear bump self._version)
  _providers: dict[key, Provider]           # ONE map for classes, instances, factories
Provider  (__slots__) kind, target, scope, is_async, params: tuple[Param, ...]
Param     (__slots__) name, lookup_key, has_default, default, marker
Compiler  (lazy, per key, on first resolve; cleared when _version changes)
  _sync:  dict[key, Callable[[], T]]
  _async: dict[key, Callable[[], Awaitable[T]]]  # only for keys whose subtree has an async factory
  _singletons: dict[key, T]
```

- `get(key)`: `fn = _sync.get(key)` → if missing, compile → `return fn()`. Singleton cache hit is the first line of `get`.
- Compilation analyses the target **once** (`get_type_hints` with `inspect.signature` fallback; fast path reads `__code__`/`__annotations__` directly when no string annotations). Lookup rule decided at compile time: `Inject[...]` marker → param name if bound → type. Every `bind` invalidates, so this is equivalent to today's per-call rule.
- Code generation: one generated function per key; transient subtrees inlined as nested constructor calls; singleton/request deps as inline dict lookups; generated source registered in `linecache` with readable names. `InjectQ(debug=True)` uses linked closures instead (prototype: ~95 % of the gain, plain tracebacks).
- Async: one generator emits sync or async source. Keys whose subtree has no async factory reuse the sync function from `aget`. `get()` on a key that needs async raises a clear `InjectionError("use aget")`.
- Cycles: detected at compile time (grey/black marking), raising `CircularDependencyError` with the path. No runtime resolution stack → the false-cycle bug disappears by construction.
- Locks: reads take none. Compilation under one `threading.RLock`. Singleton creation: per-key `threading.Lock`, double-checked; async singletons: per-key `asyncio.Future` shared by concurrent awaiters. The `thread_safe=` flag becomes a no-op kept for compatibility (deprecated).
- `validate()`, `compile()` and `get_dependency_graph()` all walk the compiled plans — one source of truth, cycles included; `compile()` raises on errors.

### 3.2 Context and scopes

```python
_current: ContextVar[InjectQ | None]
_scopes:  ContextVar[Mapping[str, dict]]   # scope name -> instance dict
```

- `ContainerContext.use()` / `use_async()` / `InjectQ.context()`: one implementation — `token = set(...)`, `try: yield`, `finally: reset(token)`, `ValueError` from a foreign context caught.
- `set_current()` returns the token; new `reset_current(token)`; `clear_current()` documented as "cannot restore an outer value".
- No `threading.local` anywhere. Threads started with `to_thread` / anyio see the caller's container and scope; plain `threading.Thread` and `run_in_executor` don't (documented).
- Scope enter = new dict in a new mapping, `token`; exit = close instances (LIFO exit stack) then `reset(token)`. Nested same-name scopes restore the outer one.
- Resolving a request-scoped key with no active scope raises `ScopeError`.
- Delete `ThreadLocalScope`, `HybridScope`, `AsyncScope`, `AsyncScopeManager`, `ScopeManager`'s thread-local state.

### 3.3 Overrides and testing

- `container.override(key, value)` pushes an entry onto an override layer checked when compiling; bumps `_version`; on exit pops and evicts **only that key's** cached singleton. Works for factory-bound keys, respects `allow_override=False` (overrides are not rebinding).
- Override layer lives in a ContextVar so concurrent tests/tasks don't see each other's overrides.
- `test_container()` / `test_mode()` set the container in `ContainerContext`.
- Rename pytest-colliding helpers: `pytest_container_fixture` → `container_fixture`, `test_container` → `isolated_container`, `TestModule` → `MockModule` (old names kept as deprecated aliases).

### 3.4 `@inject` and `Inject`

- Plan built lazily on first call (forward refs work), cached on the wrapper; rebuilt when the container `_version` changes.
- Generated wrapper fills only missing kwargs; fast path when all args are passed.
- Resolution errors → `InjectionError`; the function's own exceptions pass through unchanged.
- Sync, async, async-generator and generator functions supported; works on either side of `@classmethod`/`@staticmethod`; callables without `__name__`.
- `Inject[T]` / `Inject(T)` becomes a plain marker. Outside `@inject` it can still lazily resolve, but per access, against the current context container, no caching, no `__class__` spoofing, side-effect-free `repr`.

### 3.5 Integrations

`integrations/_common.py`: `require(pkg, extra)`, `make_dependency(key, locate)` (an `async def` that `await container.aget(key)`), one missing-container error.

- **FastAPI**: middleware sets `ContainerContext` token **and** enters `async_scope("request")`; `get_container_fastapi()` = current context, fallback `scope["app"].state`. `InjectFastAPI` dependency becomes `async def` (2× faster requests, awaits async factories).
- **FastMCP**: `setup_mcp` registers the middleware via `mcp.add_middleware`; `on_message` wraps `call_next` in `use_async` + request scope. No per-message attribute writes on the server. Import fastmcp lazily.
- **Taskiq**: a `TaskiqMiddleware` from `setup_taskiq`: `pre_execute` sets the token (kept per `task_id`), `post_execute`/`on_error` reset it. Sync tasks run via `run_in_executor` without context → keep the `broker.state` fallback in the locator.
- `integrations/__init__.py`: lazy `__getattr__` — importing one integration never imports another framework.
- One naming scheme: `Inject<Framework>`, `setup_<framework>`, `get_container_<framework>` (`InjectFastMCP`, `setup_fastmcp`, …); old names deprecated aliases.

### 3.6 Decorators, resources, modules

- One `_register(target, key, scope, container)` helper; `@singleton`, `@transient`, `@scoped`, `@register_as`, `@resource` all work bare **and** with arguments; return `Callable[[T], T]` so types are preserved.
- Resources on `ExitStack`/`AsyncExitStack`: generators wrapped with `contextmanager`/`asynccontextmanager`, init under a per-resource lock, LIFO shutdown, errors aggregated into an `ExceptionGroup`, the exception passed to teardown. `@resource` actually binds into the container with its scope.
- `ProviderModule`: uses the shared parameter plan; no `suppress(Exception)`; scope option on `@provider`; async providers awaited by `aget`.

## 4. Public behaviour changes (release notes)

- `set_current()` / `activate()` apply to the current task/thread and anything started from it via `create_task`, `to_thread` or anyio — not to other tasks on the same thread. Code that relied on that (it was the leak) must call `activate()` before starting tasks or use `use()`/`use_async()`.
- Inside FastAPI / FastMCP / Taskiq handlers, `InjectQ.get_instance()` and `@inject` resolve from the container given to `setup_*`, not the global one.
- `aget()` honours scopes; request scope is per request; resolving a request-scoped key outside a scope raises `ScopeError`.
- `get()` on a key that needs an async factory raises instead of returning a coroutine.
- `@inject` no longer wraps the function's own exceptions in `InjectionError`.
- `Inject[...]` no longer caches its value.
- `override()` only affects the overridden key and only the current context.
- A factory and a class binding for the same key: the later registration wins (or raises with `allow_override=False`).
- `thread_safe=` is accepted and ignored (deprecated) — reads are always lock-free and creation is always safe.
- `validate()` reports cycles; `compile()` raises on errors.
- Removed modules/classes (no external users found, see §5): `thread_safe_resolver`, `HybridLock`, `ThreadSafeDict`, `AsyncSafeCounter`, `ThreadSafetyMixin`, the old scope managers. Removed from `injectq/core/__init__.py` exports.
- Deprecated aliases (removed in 0.7): old integration names, old testing helper names, `ComponentContainer` & co. (if §5 decision is deprecate).

### 7.1 Publishing the benchmarks (step 12)

Today's public claims are wrong: README "Performance Highlights" and `docs/benchmark-report.md` say resolution takes ~1 µs — that is a cached singleton (default scope is singleton); a transient chain takes 24 µs in 0.5.0. ## 9. Risks

- **Generated code is harder to debug.** Mitigated by `linecache`, readable generated names, `debug=True` closure mode, and the fuzz test against the closure engine.
- **Lock-free reads on free-threaded builds.** dict reads are thread-safe in 3.13t/3.14t, but compiled-dict replacement during invalidation must be a single assignment of a new dict, never in-place mutation. Covered by a stress test.
- **Behaviour changes in §4 will break code that depended on the old bugs.** Migration guide with before/after for each.
- **Scope of the release is large.** Mitigated by the ordered PRs in §6 with the bug test suite landing first.
